## [0.16.0] — 2026-07-27

### Changed
- **`mr-goldreplay` no longer defaults a model pin — every replayed lane must be pinned explicitly (exit 2 otherwise).** The oracle row records the PIN, not the model that answered, so an unpassed flag writes evidence under a model nobody chose. That was live: `-claude-model` defaulted to `claude-sonnet-5` and the A2 weekly script passed `-codex-model` and `-glm-model` but never `-claude-model`, so **all 204 claude observations in the oracle recorded Sonnet 5 while the compiled seed rank table dispatches `claude-opus-4-8` at rank 1 on the hard classes**. The scorecard resolves cells by `(task, lane)` with no model dimension, so the router's Opus decisions were scored with Sonnet's measured results for the life of the table — `router-live 1.224× non-inferior` is a measurement of a configuration that was never deployed. `claudelane/args.go` already refused an unpinned model for this exact reason ("unpinned claude -p defaults to Sonnet 5"); the flag default reintroduced the trap one layer up. All four lane pins (`claude`, `codex`, `glm`, `local`) are now required, enforced per lane actually replayed, with an error that names the missing flags.

### Known gaps (recorded, not fixed here)
- The scorecard remains model-blind, so the A2 script deliberately keeps pinning `claude-sonnet-5`: switching to Opus now would blend two models under one `claude` key rather than update the table. The pin moves only once the evidence cell becomes `(lane, model, effort)`.
- **Effort is unmeasured entirely.** `mr-goldreplay` never passed or recorded it and the oracle row has no `effort` field, yet the seed table ranks by effort (`xhigh` rank 1, `high` rank 2). Those rankings carry no evidence.
- **Gold-set coverage is 5 of the router's 15 classes** (`agentic-coding`, `research`, `review`, `extraction`, `quick-edit`). Ten classes have never been measured, and the scorecard's own note records that production `classify.go` disagrees with the gold labels on 48/56 tasks.

## [0.15.0] — 2026-07-25

### Fixed — review round 4 (Opus, 10-agent panel; verdict DO-NOT-MERGE, one blocker with a one-token fix)

- **BLOCKER — round 3's resolver `break`ed on the FIRST `.Env` assignment after a spawn**, so an ambient overwrite following the scrub was never examined. That regressed a capability round 2 had, and every doc in the tree — `ROUTER_BIBLE.md`, the resolver's own comment, the canary's comment, this changelog — said "the LAST assignment decides". The reviewer reproduced it A/B/A against an isolated export and confirmed the one-token remedy; it is applied, and pinned by `TestSpawnResolverRules` so round 5 does not rediscover it.
- **A scrub the default path never runs is not a scrub.** `if len(req.Env) > 0 { cmd.Env = childEnv(…) }` left `cmd.Env == nil` — full ambient inheritance — on the common path and still passed. The resolver now tracks block depth: an `.Env` assignment nested deeper than its spawn is conditional and cannot be credited.
- **Scrub credit is now a BASE check, not a mention.** `cmd.Env = append(os.Environ(), childenv.Scrub(pins)...)` was credited even though the ambient environment is the base — the same mention-vs-dataflow defect fixed one level up in round 3, one level down. `append(X, …)` recurses into `X`, which is the shape codexlane and mr-scorecard legitimately use.
- **Helper credit requires EVERY environment-returning path to carry the scrub.** It was existential, so a helper with one clean and one dirty return laundered every call site.
- **An aliased `import ex "os/exec"` was invisible** to the resolver *and* to the accounting tripwire meant to catch under-counting. The local import name is now resolved per file.
- `nonLaneCommands` no longer exempts shells and package managers (`powershell`, `bash`, `sh`, `cmd`, `npx`, `npm`, `go`, …), each of which can start a model lane — the list contradicted the invariant it serves. It is now `git` plus the kill family, which is what the tree's real unscrubbed spawns need.
- `-d/--debug`'s OPTIONAL value was forwarded unjudged, so `-extra "-d ../client-secret"` exited 0 with the path in argv — the one shape the refusal list did not cover. Path-shaped optional values are now refused; inert filters (`--debug api`) still work.
- A quota or paced deferral receipt's `egress_gate` had **no test**, so `SECURITY.md`'s "every dispatch records its gate decision" was unenforced; `TestGLMDeferralReceiptCarriesTheEgressGate` now pins it. The Bible verify-pointer arity guard was `< 14` against 15 pointers, letting B14's behavioural pointer be un-cited silently.
- **MIGRATION.** `mr-orchestrate run -lane glm -extra "--add-dir <dir>"` worked one commit ago and now exits 6, even when `<dir>` is allowlisted. That is deliberate (see round 3), and it is a behaviour change rather than a pure hole-closing for anyone driving the CLI by hand: pass the directory as `-cwd` instead, with the repo in `glm_allow_repos`.
- **Full mutation matrix re-run after every change above — 19/19 defeat classes caught:** the scrub deleted at each of the 10 spawn sites, plus ambient-overwrite, conditional scrub, append-argument scrub, laundering helper, rebind-after-scrub, `&exec.Cmd{}` literal, var-decl spawn, second-spawn-in-a-scrubbing-file, and comment-only claim. B12 re-measured 18286 against a ceiling of 18300.

### Fixed — review round 3 (Opus, 13-agent panel; verdict DO-NOT-MERGE, 3 blockers, all reproduced live)

Round 2 built the gate. Round 3 proved two of its fixes still leaked, in the same function, for new reasons.

- **BLOCKER — the `--extra` gate and the CHILD disagreed about what a relative path names.** `egress.Check` resolved a relative `--extra` value against the ORCHESTRATOR's working directory; the token is forwarded verbatim and the child resolves it against `cmd.Dir`. Standing deeper in the tree than `--cwd`, `--extra "--add-dir ../client-secret"` exited **0** with `egress_gate: "repository context allowlisted"` while the child was handed a directory outside the allowlist. The absolute spelling of the same directory was correctly refused — so the verdict was a pure function of spelling.
- **BLOCKER — a variadic collector left open across a skip-counted flag swallowed a path silently.** `--add-dir --output-format <dir>` produced **neither** a gated path **nor** an unaccounted token: variadic collection stopped at the `-` prefix, then `--output-format`'s skip counter ate the directory. Commander, by contrast, takes the required value and *keeps collecting* for the variadic option — the shipped binary adopted the directory. 28/28 dispatcher combinations exited 0 with the client path in argv.
- **The fix is to stop re-implementing another program's argument parser.** This gate is not, and cannot be, a second implementation of commander: its behaviour around variadic options, optional values and end-of-flags is subtle, partly undocumented, and free to change in any upstream release. Two designs tried to *gate the paths* and both were defeated. So a third-party dispatch may no longer pass a path-bearing flag **at all** — `egress.RefuseExtras` accepts only flags provably incapable of naming a path and refuses everything else, including `--add-dir`, `--mcp-config`, `--settings`, unrecognized flags, bare positionals and anything after `--`. Repository context reaches a third-party lane through `-cwd` plus the allowlist, gated in one place with one rule. Nothing in this repo passes `--extra` to a third-party lane (`mr-goldreplay` gates `-claude-extra` on `lane == "claude"`), so this closes a hole rather than removing a capability.
- **BLOCKER — B13's "per-site" check was per-variable-NAME.** It kept one verdict per identifier and stamped it onto every spawn bound to that name, so four ordinary refactors defeated it with the suite green: rebinding the variable after the scrub, an earlier unscrubbed spawn being back-credited by a later scrub, a lexically distinct `cmd` in a sibling block, and a retry spawn **on the production claude dispatch path** — where a `claude` child then ran with `Env == nil`, full ambient inheritance. Now resolved in statement order: a spawn is scrubbed only if an assignment to *its* `.Env` deriving from `childenv.Scrub` follows it before the variable is rebound. **Mutation-verified: all four round-3 bypasses caught, and the round-2 matrix re-verified against the rewritten resolver — 10/10 sites.**
- Follow-ups from the same panel, fixed here rather than deferred: the scrubber-helper credit was **mention-based**, so a helper that called `Scrub` and returned `os.Environ()` would have laundered every call site — now it requires the scrub to reach the RETURNED value, via minimal local dataflow (mutation-proven to reject the launder while still accepting the real `childEnv`); an `&exec.Cmd{…}` composite literal was invisible to both the resolver and its own accounting tripwire; `var cmd = exec.Command(…)` was misreported as "spawns with no handle"; `-d/--debug [filter]`'s optional value made a legitimate diagnostic dispatch impossible; and the Bible verify-pointer canary captured only the FIRST backticked pointer per invariant, leaving B14's behavioural pointer — the load-bearing half — unenforced (mutation-proven fixed).
- **CONCEPT-CHANGE:** B13's Bible entry now states that checking is per site in statement order. `docs/bible.sum` updated. B12 note corrected: round 2 recorded 17973 while the tree held 18003 — exactly the drift a previous audit flagged; now 18168 measured, ceiling held at 18300.

### Fixed — review round 2 (Opus, 16-agent adversarial panel; verdict DO-NOT-MERGE, 4 blockers, all reproduced live)

The first round of this PR built the gate. The second round proved it did not hold. Every finding below was demonstrated with a running dispatch, not argued.

- **BLOCKER — `--add-dir` is VARIADIC, so the gate inspected one directory and shipped the rest.** The extractor modelled `--add-dir` as arity-1. The registration read out of the shipped `claude` executable is `--add-dir <directories...>`; `--extra` is split on whitespace and re-emitted at the tail of argv, so commander's variadic sweep took every remaining token. Measured: `--add-dir <allowed> <client>` exited **0** with the client checkout in argv and the receipt reading `egress_gate: "repository context allowlisted: <allowed>"` — not merely ungated, affirmatively **mis-certified**. `--add-dir ../lib ../shared` was enough; no adversary required. `--mcp-config <configs...>`, `--file <specs...>` and `--sparse <paths...>` are variadic too and had **no** gate at all.
  Fixed by consuming the whole variadic run, and — because a CLI with 82 options and 7 variadic ones will keep growing — by inverting the posture: `egress.Extras` enumerates the flags that **cannot** carry a path, gates the values of those that can, and reports everything else as unaccounted, which the dispatcher **refuses**. A gate that lists only the dangerous flags fails silently the first time a new one ships; one that lists the safe flags fails loudly, and a loud failure gets fixed. Live: exit **6** naming the refused path.
- **BLOCKER — a Windows junction walked straight through the link guard.** Go reports a junction as `ModeIrregular`, not `ModeSymlink`, so `filepath.EvalSymlinks` returned the path **unchanged with a nil error** and `abs = real` was a self-assignment. The asymmetry is what made it dangerous: `mklink /D` (symlink) needs elevation, `mklink /J` (junction) does not — so the only case the guard caught was the one requiring admin, and the one any user, installer or build script creates freely did not. Measured: a junction inside the allowlisted repo pointing at a client checkout exited **0**, with the child physically inside the client tree and the receipt certifying "allowlisted".
  Fixed with real OS canonicalization (`GetFinalPathNameByHandleW` over stdlib `syscall` — this module has zero dependencies and keeps them), a non-existent leaf resolved through its deepest existing ancestor, and hard fail-closed on anything unresolvable. Live: exit **6**. Also found doing this: `filepath.Abs` **mangles** a UNC path into `<current-drive>\server\share\…`, a real local directory name, so UNC is now handled explicitly rather than localised.
- **BLOCKER — B14 is a token grep and cannot prove obedience.** Its only assertion is that `egress.Plan` is *called*. Two compiling mutations (`_ = planDir`; discarding the returned dir at the call) keep it green, keep the full suite green, and export the caller's repository while the receipt still reads "prompt-only ENFORCED". Fixed by adding what was missing: **behavioural** tests (`cmd/mr-orchestrate/egress_dispatch_test.go`) that assert on `effective_cwd` and the exit code. **Verified: B14 stays green under both mutations; the behavioural tests catch both.** B14 is now documented as a tripwire for lanes not yet written, keyed on the `run` command's own lane switch so a *reachable* lane cannot lack a dispatcher, and its old `len(bodies)==0` tripwire — permanently satisfied by glm, so it could never fire — is gone.
- **BLOCKER — B13 was a per-FILE grep, so one scrub covered every spawn in the file.** codexlane has 3 spawns and 1 scrub, locallane 2 and 1, claudelane 2 and 1. Adding a fresh unscrubbed `claude -p` spawn to any of them was green, and so was overwriting a scrubbed `cmd.Env` with the ambient one. Rewritten as a structural per-SITE check over the AST (`internal/canary/b13.go`): each `exec.Command` site is resolved to its `*exec.Cmd` variable, and the **last** assignment to that variable's `.Env` must derive from `childenv.Scrub` — with `cmd.Env = append(cmd.Env, …)` recognized as extending rather than replacing, and one level of same-package indirection (the claude lane's `childEnv` wrapper) admitted structurally rather than by name. Exemption is decided by the spawn's own literal `argv[0]`; a **variable** command name is never exempt. **Mutation-verified: 4 defeat classes × 10 spawn sites, every one caught.** Its own accounting tripwire then found a spawn the walk had missed (a package-level func literal), and the check found two genuinely unscrubbed sites: `mr-goldverify`'s helper, which runs the gold task's own arbitrary verify command, and `codexlane.VersionGate`.
- Nine minors from the same panel: `SECURITY.md` claimed `egress_prompt_only_denied` closes third-party lanes entirely (it closes only the prompt-only path) and that `--add-dir` outside the allowlist fails closed (it did not); quota and paced deferral receipts dropped `egress_gate` although the gate had already ruled, making "every decision lands on the receipt" false for every deferral; relative `glm_allow_repos` entries resolved against the current directory, so `"."` self-allowlisted any checkout — now refused, along with drive-relative `C:repo`; `claudelane.RunReq.Env`'s doc still said "APPENDED to `os.Environ()`", wording that predated the scrub; `childenv_test.go`'s docstring claimed more than the test proves; and `childenv.Removed`'s "one-time warning" had one caller and re-printed per dispatch while eight sites warned not at all — now `childenv.WarnOnce`, where the warning belongs to the scrub rather than to one lane.
- **CONCEPT-CHANGE:** B13's Bible wording was absolute ("no process this system starts") while `git` and `taskkill` spawns legitimately inherit the ambient environment — an invariant stated wider than it is enforced is a false invariant. Both B13 and B14 are rescoped to what the canaries actually check, and B14 now names its behavioural counterpart as a second verify pointer. `docs/bible.sum` updated.
- B12 complexity budget 17500 → **18300** (measured 17973), raised consciously in the PR that needs it: the growth is `internal/canary/b13.go`, a structural check replacing a textual one whose three successive shapes all passed while the invariant was broken. That is the trade this budget exists to make deliberately, not to forbid.

### Added
- **Third-party egress gate** (`internal/orch/egress`, R3). GLM is rank 1 for the default coding classes, runs with `cmd.Dir` set to a real repository, and shipped prompt **plus repo context** to a PRC-hosted provider with no gate of any kind — while the operator's own recorded rule required exactly this gate before the Gemini free tier could be seated. Repo context to a third-party lane now requires an explicit allowlist (`glm_allow_repos`); prompt-only dispatches are allowed unless `egress_prompt_only_denied`; unresolvable paths and an empty allowlist **fail closed**; a path that merely shares a prefix with an allowlisted repo is not "inside" it. **`--force` does not bypass** — a data export is not a quota judgement (same force-proof class as the R10 billing hard-stop). Denials are terminal (**exit 6**, distinct from a quota deferral because retrying cannot help) and every decision — allow or deny, with its basis — lands on the receipt as `egress_gate`. **A CRITICAL found in review:** an empty `cwd` is not "no repo context" — `os/exec` runs the child in the PARENT's directory, so a dispatch launched from inside a client checkout exported that checkout while the receipt recorded `prompt-only`, defeating the gate on its most common invocation. `egress.Plan` now resolves the inherited cwd and, when it is not allowlisted, makes prompt-only TRUE by running in a neutral empty temp dir — enforced rather than assumed (live-proven: `effective_cwd` becomes `…\Temp\mr-neutral-*`). `--add-dir` inside `--extra` is gated as the second export channel it is.
  The gate's PREDICATE is lane-generic (`egress.ThirdPartyLanes` covers groq, cloudflare, gemini, nim), but **enforcement is not inherited** — every adapter must call `Plan`, and today exactly one does because glm is the only shipped third-party lane. Rather than leave that as prose, the new **B14 canary fails any `run<Lane>Lane` dispatcher for a lane in that set that never reaches the gate**, so seating a free lane without wiring it is a red test, not a silent export.
- **Child-environment credential scrub** (`internal/orch/childenv`, R4). Lane children inherited the ambient environment unfiltered (`cmd.Env` left nil inherits everything). In headless mode — all meta-router ever spawns — Claude Code honours an ambient `ANTHROPIC_API_KEY` **unconditionally, ahead of OAuth and bypassing the approval gate**, so one `setx` after an SDK experiment would convert every "subscription" dispatch into metered spend while receipts still read `cash_usd: 0`; `CLAUDE_CODE_SIMPLE` is likewise equivalent to the `--bare` flag the argument builder explicitly bans. Deny-list (API keys, auth tokens, base URLs, OAuth-token FDs, cloud-routing switches, `ANTHROPIC_DEFAULT_*` model pins, `OPENAI_API_KEY`) applied to the ambient env **before** each lane appends its own deliberate pins — so the GLM lane's intentional base-URL/token still work — with a one-line warning naming anything dropped. Deny-list rather than allow-list because a strict allow-list plausibly breaks every Windows spawn.
  **Honest history, because "fixed" was claimed too early twice here.** The first pass wired 2 of 5 spawn sites; review found `probe`, `verify` and `locallane` still handing children the ambient env — and probe/verify make LIVE billable calls that write no receipt, so unscrubbed spend there is invisible. The B13 canary added to stop that recurring then had the same defect in miniature, caught by mutation-testing it rather than by trusting it: (a) it accepted a *comment* mentioning `childenv.Scrub` as proof of a call, so deleting the call still passed — canaries that grep for a call now strip comments first (`canary.StripGoComments`, unit-tested both directions); and (b) its "process-control helper" escape hatch keyed on `"taskkill"`, which claudelane, codexlane and locallane all contain to kill a timed-out child — exempting the three most important lane spawn sites. The heuristic is now an explicit one-entry allowlist with a stated reason (`mr-goldverify`, which spawns only git/go/the task's own verify command). **Mutation-verified: deleting the scrub at each of the 9 spawn sites is now caught at all 9.** `mr-goldreplay` gained a scrub too — it spawns the orchestrator and verifier, and a weekly unattended run of ~150 dispatches is the last place to rely on downstream hygiene.
- `status` now surfaces **`a2_alert`**: the weekly drift verdict had **no reader anywhere**, so a DRIFT alarm reached nobody. Alert files are read BOM-tolerantly — Windows PowerShell's `-Encoding UTF8` prepends a BOM that `json.Valid` rejects, which would have silently dropped the alarm again (caught in rehearsal); a UTF-16 file or corrupt JSON now warns on stderr instead of reading as "absent".

A verdict frozen at last month's `ok:true` renders identically to a fresh pass, so the alert is now AGED (>8 days = one missed weekly run): stale, un-timestamped and future-stamped verdicts each say so. Absence stays silent, because the task is deliberately disabled until the replay leg is rehearsed. Same F18 class as `policy_watch_stale`.

True of the surfacer, flatly false of the orchestrator, which exists to dispatch prompts to Claude/Codex/GLM. B13's canary shipped in this PR before its invariant was written down — an invariant enforced by a test but absent from the register is exactly the drift the concept gate exists to catch. `docs/bible.sum` updated.

## [0.13.0] — 2026-07-25

### Fixed
- **The quota banner told the truth about nothing.** `cmd/mr-hook`'s render printed a bucket's `used_pct` with no expiry test, so an EXPIRED window appeared as live pressure: on the primary machine the per-prompt hint read `claude 5h 85% THROTTLED` off a window that had reset 25h earlier, while `route` (which does guard expiry) saw an open lane. ### Added
- **`mr-orchestrate fleet`** — the deployed-binary check whose absence let an admission fix from 2026-07-19 sit undeployed through v0.10.0, v0.11.0 and v0.12.0 (B11 version-parity is SOURCE-only: it never looks at `~/.meta-router/bin`). Reads each deployed binary's embedded VCS revision via `debug/buildinfo` and flags any that differs from the reference — revision, not version string, because sibling binaries are versioned independently by design (adjudicated). It is honest about what it cannot know — every unverifiable state counts against the fleet instead of passing quietly: no reference revision ⇒ `staleness_undetermined`; an unstamped binary ⇒ `unstamped`; an unreadable one (deploy in progress, truncated copy) ⇒ `unreadable_count`; an empty bin dir says NO BINARIES FOUND rather than "uniform". Revisions compare by PREFIX, so a 7-char `git rev-parse --short` matches a full stamp. `-expect <rev>` supplies the reference, and deploys inject `-ldflags "-X main.buildRev=$(git rev-parse HEAD)"` — Go omits AUTOMATIC vcs stamping for worktree builds, which is precisely how this project deploys, so relying on it alone left the check inert on the only path that matters. `-strict` exits 1. Run against the live fleet with an explicit reference: 6 of 7 binaries stale.
- `mr-hook -version` (a deployed hook could not previously be asked what it was), and `usage` now lists `poll`, `quota-parity`, `profiles` and `fleet` — all dispatched but undocumented.
